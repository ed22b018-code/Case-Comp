# MAI Explorer — Project Status
_Last updated: 2026-07-16 · Milestones 1–3 complete_

## What is built

### Interactive Front-End (M1 + M3)
React 18 + Vite app at `http://localhost:5173` (`npm run dev`).

| Pane | Description |
|------|-------------|
| **Map** | India choropleth — 710 districts, Score or Archetype color mode |
| **Opportunity Matrix** | 2×2 scatter: X=current, Y=growth Δ, bubble=demand pillar; quadrant lines at national medians |
| **Deployment Simulator** | N-district shortlist; 4 strategies (Maximize Current / Future / Balanced / Emerging Bets); state filter + exclude list |
| **Rankings Table** | Sortable/filterable leaderboard, all 710 districts |
| **District Panel** | Slide-in detail with pillar waterfall + radar chart |

**Export capability** — all views:
- Map: PNG (2× DPI, full view with legend) and SVG (vector paths)
- Matrix: PNG (full view) and SVG (chart body)
- Simulator: CSV (9 columns, filtered shortlist)
- Rankings: CSV (8 columns, sorted/filtered)

### Scoring Pipeline (M2)
`python pipeline/run_pipeline.py` → writes `data/scores.json` + `data/clusters.json`.

Steps: ingestion → imputation (hierarchical → KNN → MICE) → index engine (arithmetic + geometric) → CAGR forecast → sensitivity (±20% weight perturbation) → k-means clustering → reports → JSON output.

Pipeline runs a **preflight check** on startup that validates:
- Weights sum to 1.0 ±0.001 per therapy
- Every indicator has a valid pillar and direction
- Every `READY` indicator has a file that exists

### Tooling (M3.5)
- `pipeline/DATA_ONBOARDING.md` — step-by-step guide for adding real indicator data
- `pipeline/raw/templates/` — 12 ready-to-fill CSV templates (one per indicator)
- `pipeline/crosswalk/reconcile.py` — fuzzy-match CLI tool for real-data name reconciliation
- `pipeline/config/manual_overrides.csv` — slot for manual name fixes (created on demand)

## What is synthetic vs real

### Synthetic (must replace before final submission)
All 12 indicator values are generated by `pipeline/generate_synthetic.py` using a deterministic djb2 hash. **No real data has been ingested.**

The spatial patterns (state clustering, therapy Spearman correlations) are realistic but not empirically calibrated.

### Real (already in place)
| Component | Source |
|-----------|--------|
| District geography | 2011 Census GeoJSON (759 features, 710 with dt_code + name) |
| District crosswalk | Built from GeoJSON (724 rows, 710 unique canonical districts) |
| Pillar structure | Grounded in NFHS-5, NHP, HMIS, Census, RBI indicators |
| Therapy weights | Literature-anchored placeholders (Chronic: monetization-heavy; Acute: demand + access) |
| Scoring method | Geometric aggregation (HDI-2010 non-compensatory precedent) |

## Remaining steps to final submission

### Step 1 — Reconcile district names (do first, per indicator)
```bash
python pipeline/crosswalk/reconcile.py <source_csv> --name-col <col> \
    --output pipeline/config/<source>_reconciliation.md
```
Review fuzzy matches. Add corrections to `pipeline/config/manual_overrides.csv`. Re-run.

### Step 2 — Drop 12 real indicator CSVs
Place each at `pipeline/raw/indicators/<indicator_id>.csv` (format: `district_id, value, year`).
Templates at `pipeline/raw/templates/<id>_TEMPLATE.csv`.

Priority order (highest signal-to-noise first):
1. `urban_pop_pct` — Census 2011, clean, complete
2. `literacy_rate` — Census 2011, clean, complete
3. `pop_growth_rate` — Census 2001 + 2011
4. `health_insurance_cov` — NFHS-5 2019-21
5. `per_capita_nsdp` — RBI/MoSPI
6. Remaining 7 in any order

### Step 3 — Flip status to READY
In `pipeline/config/index_config.yaml`, change `status: TODO` → `status: READY` for each indicator.

### Step 4 — Calibrate weights (optional for competition)
Current weights are equal-weight placeholders. The sensitivity report at
`pipeline/reports/output/sensitivity_summary.md` shows Spearman rank-stability
under ±20% perturbation — use this to identify which pillar weights matter most.
Consider PCA/entropy weighting if time permits.

### Step 5 — Run pipeline
```bash
python pipeline/run_pipeline.py
```
Regenerates `data/scores.json` and `data/clusters.json`. App hot-reloads.

### Step 6 — Validate (if IPM/IQVIA data available)
Place district pharma sales at `pipeline/raw/validation/validation_proxy.csv`
(columns: `district_id, sales_value`). The validation harness activates automatically.

### Step 7 — Export deck assets
From the running app:
- Map PNG (score + archetype modes) → slide backgrounds
- Matrix PNG → opportunity quadrant slide
- Simulator CSV → shortlist table slide
- Rankings CSV → appendix
